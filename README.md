# Поиск по корпоративным регламентам

Локальный прототип для ИИкузницы. Веб-форма загружает четыре DOCX заказчика, показывает выдержку с указателем на раздел или строку таблицы, задаёт уточнение при пересечении регламентов и направляет вопросы без подтверждения в очередь службы качества. Сотрудник службы качества может подтвердить ответ и привязать его к регламенту. При повторном вводе того же вопроса ответ из базы помечается отдельным источником.

## Запуск

Из папки `prototype` в PowerShell:

```powershell
python -m pip install -r requirements-semantic.txt
.\prepare-model.ps1
$env:QUALITY_TOKEN = [guid]::NewGuid().ToString('N')
python -m uvicorn app:app --host 127.0.0.1 --port 18766
```

Откройте [веб-форму](http://127.0.0.1:18766/). Для раздела службы качества используйте значение переменной `QUALITY_TOKEN` из той же сессии. Для запущенного из Codex экземпляра значение хранится в локальном файле `runtime/quality-token.txt`. SQLite сохраняет обращения между запусками в `runtime/quality.sqlite3`. Путь можно изменить через `QUALITY_DB`.

Для режима без модели достаточно `requirements.txt` и пустой папки по пути `E5_MODEL_DIR`. При наличии модели она работает на CPU. Индекс строится при запуске, документы и запросы обрабатываются локально. [Multilingual E5](https://huggingface.co/intfloat/multilingual-e5-small) · [Квантованная версия ONNX](https://huggingface.co/Xenova/multilingual-e5-small/tree/761b726/onnx)

По умолчанию приложение читает `../private-corpus`. Если файлы находятся в другом месте, задайте `CORPUS_DIR`. Ожидаемые имена и исходные идентификаторы находятся в `retrieval.py`. После обновления корпуса перезапустите приложение.

## Контейнер стенда

Из `prototype` после подготовки модели и регламентов:

```powershell
$env:QUALITY_TOKEN = [guid]::NewGuid().ToString('N')
docker compose -p iikuznitsa-stand up --build -d --wait --wait-timeout 120
```

Контейнер поднимает [локальный стенд](http://127.0.0.1:18767/) и проверяет, что доступны все четыре документа и модель E5. Документы и модель монтируются только для чтения. Обращения хранятся в отдельном томе Compose. Каталоги можно переопределить через `STAND_CORPUS` и `STAND_MODEL`, порт через `STAND_PORT`. При размещении на сервере публикуйте URL через HTTPS-прокси. Файлы документов, модель, БД и ключ службы качества подключайте отдельно от исходного кода.

Для хостинга с лимитом 512 МиБ соберите образ из `Dockerfile.cloud`. В этой сборке таблица эмбеддингов E5 читается с диска через отображение файла в память. Веса и порядок вычислений модели сохранены.

```powershell
docker build -f Dockerfile.cloud -t iikuznitsa-cloud .
docker run --rm --memory 512m --cpus 0.2 -p 127.0.0.1:7860:7860 iikuznitsa-cloud
```

Сервис слушает HTTP на порту 7860. При первом запуске скачивает четыре регламента по ссылкам организатора, сверяет их контрольные суммы и строит индекс. Проверьте, что `/api/catalog` сообщает о четырёх источниках и режиме `hybrid`. Для работы очереди качества передайте `QUALITY_TOKEN`. Для сохранения ответов после пересоздания контейнера подключите том к `/opt/demo/state` с правом записи для UID 1000.

## Сценарии демонстрации

1. Спросить «Кто назначает руководителя проекта?» и выбрать «ДБРЦТ · проекты». Получить выдержку из пункта 2.1.2 о назначении РП на пресейл.
2. Выбрать «Дирекция ИБ · проекты» и спросить «Что делать с расхождениями в себестоимости проекта?». Агент уточнит, меняют ли расхождения себестоимость. После выбора покажет применимую часть п. 3.5. Ответ «Не знаю» создаст обращение.
3. Спросить «Какой шаблон договора использовать для проекта по итогам конкурса?» по регламенту Технической дирекции. Ответить, входил ли проект договора в конкурсную документацию. Агент процитирует выбранную ветку п. 7.2.
4. Спросить о переносе активированной лицензии и получить номер обращения. Утвердить учебный ответ в очереди, затем проверить переформулировку о переоформлении ключа на новую организацию. Отмена переноса создаёт отдельное обращение. [Полный сценарий](DEMO.md)

Поиск выдаёт фрагменты из регламентов. Он сочетает текстовое совпадение и ранжирование E5 при выбранном процессе. Генерация ответа отсутствует. Когда пункт явно формулирует условие и альтернативу со словами «в иных случаях», «в остальных случаях» или «иначе», агент уточняет недостающую деталь и выводит выбранную ветку. Подтверждённые ответы находятся по точному совпадению или по схожему смыслу и ключевым признакам вопроса. При похожей формулировке пользователь подтверждает применимость ответа. Для очереди применяется локальный интерфейс службы качества.

## Проверка поиска

```powershell
python benchmark.py
python benchmark.py --model runtime/e5
python evaluate.py --model runtime/e5
```

Проверка использует 12 ручных сценариев на четырёх предоставленных регламентах. Если ожидается ответ, проверяется конкретный пункт. Эта выборка позволяет сравнить варианты поиска и найти ошибки, её размер не позволяет оценить качество на всём корпусе.

Расширенный набор содержит 32 вопроса. Отдельно учитываются ответы с другим пунктом, уточнения и воздержание от ответа. [Сценарий демо и схемы](DEMO.md)

Расчёт токенов для этой версии даёт ноль. Стоимость запроса нужно дополнить измеренной нагрузкой и ценой выбранного хостинга. Бриф указывает до 200 запросов в день. [Материалы задачи](https://drive.google.com/drive/folders/1toFmwPD6c6XcCQzBcbfJPskJGzMh23tY)
